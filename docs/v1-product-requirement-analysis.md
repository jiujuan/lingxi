我认为**MVP 的目标不是"功能最少"，而是"形成完整闭环"**。

对于 AI 客服知识中心，第一个版本应该满足一句话：

> **企业上传知识 → AI 自动整理 → 客服和客户都能用 → 企业知道 AI 有没有真正解决问题。**

所以 **MVP 不应该超过 8 个一级模块**，但每个模块都要做到企业可用。

------

# 推荐的数据库设计（MVP）

建议一开始就按"领域模型"设计，而不是按页面设计，避免后续重构：

| 领域     | 核心实体                                            |
| -------- | --------------------------------------------------- |
| 知识管理 | Knowledge、Document、Chunk、Category、Tag、Version  |
| AI 检索  | Embedding、RetrieverConfig、Citation                |
| 客服     | Conversation、Message、Session                      |
| 工单     | Ticket、TicketComment、TicketStatus                 |
| 用户权限 | User、Role、Permission、Department                  |
| 运营分析 | SearchLog、Feedback、MissedQuestion、KnowledgeStats |
| 系统配置 | ModelProvider、PromptTemplate、SystemConfig         |

------

## 我建议的 V1 原则：**做"企业级"，但不是"大而全"**

不要急于加入 CRM、ERP、订单系统、自动退款、Agent 工作流等复杂能力。第一版只需要证明三件事：

1. **知识能够高质量接入和治理**（上传、解析、审核、版本）。
2. **AI 能基于知识稳定回答问题**（RAG + 引用来源 + 多轮对话）。
3. **系统能持续变聪明**（未命中分析 → 补充知识 → 命中率提升）。

这三个闭环一旦跑通，就已经具备企业付费的基础；后续再叠加 Agent、Workflow、业务系统集成，就可以自然演进为完整的 AI 客服平台，再进一步升级为 AI 知识中台。
