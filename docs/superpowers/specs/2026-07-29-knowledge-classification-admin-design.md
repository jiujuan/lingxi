# 知识库分类管理页面改版设计

**日期：** 2026-07-29  
**范围：** `web/admin` 知识库分类管理页面

## 目标

将后台“知识库分类”页面改为参考稿的分类管理样式。页面以列表形式展示分类，支持在同一页面内管理知识库空间、部门和专题/项目三种分类维度。

## 页面结构

页面由以下区域组成：

1. 标题区：标题“知识库分类管理”、说明文字和与当前 Tab 对应的新增按钮。
2. 分类 Tab：知识库空间、部门、专题/项目。Tab 含图标、当前条目数和蓝色激活下划线。
3. 工具区：当前 Tab 范围内的搜索输入框。
4. 分类列表：白色低圆角表格容器，含适合当前类型的表头、行首图标、状态标签和文字操作。
5. 分页区：沿用本地前端数据量的分页样式；本次不改变后端列表接口的分页契约。

桌面端使用表格列布局；窄屏下列表保持可读的单列信息块，避免水平溢出。

## Tab 行为

### 知识库空间

- 展示空间名称、编码或说明、统计信息、状态、更新时间和操作。
- 支持搜索、新增、编辑、删除。
- 删除存在关联文档的空间时，显示当前已有的文档迁移弹窗；迁移完成后允许用户再次确认删除。

### 部门

- 展示部门名称、编码、成员数、创建时间和操作。
- 支持搜索、新增、编辑、删除。
- 使用现有 `listDepartments`、`createDepartment`、`updateDepartment`、`deleteDepartment` 接口。
- 部门删除失败时展示后端错误信息，不在前端绕过部门归属或成员校验。

### 专题 / 项目

- 展示名称、类型、所属知识库空间、所属部门、统计信息、状态和操作。
- 支持搜索、新增、编辑、删除。
- 由于分类接口要求 `spaceId` 和 `departmentId`，Tab 工具区保留紧凑的空间与部门筛选器；分类列表、统计和新增默认值都受当前筛选范围约束。
- 新增和编辑弹窗中允许选择空间、部门和类型。
- 删除存在关联文档的分类时，继续使用已有文档迁移弹窗。

## 弹窗与交互

### 新增 / 编辑

- 新增和编辑均为居中弹窗，不跳转页面。
- 弹窗采用参考稿的紧凑表单样式：约 460px 宽、标题、右上角图标关闭按钮、字段标签、底部“取消 / 保存”按钮。
- 空间、部门、专题/项目分别保留各自所需字段；不增加当前后端模型没有的负责人、截止时间等字段。

### 删除确认

- 用自定义 `ClassificationDeleteConfirmModal` 替代原生 `window.confirm`。
- 弹窗含标题、关闭图标、红色警示图标、具体删除对象名称、影响说明、取消和红色“确认删除”按钮。
- 空间删除文案说明关联文档会保留但失去分类；专题/项目删除时由接口冲突结果决定是否打开迁移流程；部门删除影响由后端错误信息说明。
- 关闭、取消和确认删除期间的禁用状态均应可访问，图标按钮提供 `aria-label`。

## 组件与数据流

- 重构 `KnowledgeClassificationPage`，保留现有空间、分类、统计和迁移调用逻辑。
- 新增部门的加载和 CRUD 状态处理，并依照现有 org API 调用。
- 将当前 Tab、搜索词、分类筛选和各模态框状态保留在页面容器中。
- 以小型展示组件或清晰的行渲染函数区分三类列表，避免把三个 Tab 的列定义混杂在同一段 JSX 中。
- 复用并重设 `KnowledgeSpaceModal`、`KnowledgeCategoryModal`；新增部门表单弹窗和删除确认弹窗。

## 错误与刷新

- 加载失败在当前列表上方展示错误状态，保留刷新入口。
- 新增、编辑、删除成功后展示通知，并刷新受影响的列表与统计。
- 切换 Tab 不丢失其他 Tab 的服务端数据；当前范围变化时专题/项目列表和统计重新加载。
- 迁移成功后刷新空间、专题/项目、统计和当前筛选数据。

## 验收

- 三个 Tab 可切换，标题、主按钮、搜索和表格列随 Tab 改变。
- 空间、部门、专题/项目均可通过弹窗完成新增、编辑和删除。
- 三类删除均先打开自定义删除确认弹窗；关联文档的空间和专题/项目仍可进入迁移流程。
- 已有分类 API 请求负载、权限控制和统计展示保持正确。
- 更新 `web/admin/tests/t09_knowledge_playwright.py`，覆盖三个 Tab CRUD、删除弹窗以及现有迁移场景。
- 运行 `npm run build`、相关 Playwright 验收，并在桌面与 390px 宽度下检查布局、交互和控制台错误。
