# 角色管理设计

## 目标

在后台侧边栏“用户管理”下方增加“角色管理”菜单和独立页面。该页面复用用户管理的列表、筛选、分页、操作按钮与响应式视觉规范，为当前租户提供角色查询、创建、编辑、删除和权限分配能力。

实现采用独立角色领域模块：路由、服务、仓储、请求/响应 schema 和前端 feature 均不继续堆叠到用户管理模块中。现有 `Role`、`RolePermission` 与 `UserRole` 数据模型保留并扩展。

## 范围与规则

- 角色列表支持按角色名称或编码搜索并分页展示。
- 列表列包括：角色名称、角色编码、作用范围、已关联用户数、权限数、创建时间和操作。
- 可创建、编辑、删除自定义角色，并在创建或编辑时为角色分配系统权限。
- 每个租户内角色编码唯一；角色名称和编码为必填字段。
- 本期角色作用范围固定为 `TENANT`，在详情和表单中明确展示。
- 初始化的 `SYSTEM_ADMIN`、`KNOWLEDGE_ADMIN`、`EMPLOYEE` 角色标记为内置角色；内置角色仅允许查看，不能编辑或删除。
- 已关联一个或多个用户的自定义角色不能删除。删除请求返回明确业务错误：`请先解除关联用户后再删除`。
- 删除未关联用户的自定义角色时，同时删除它与权限之间的关联记录。
- 所有查询、权限校验和写入均以当前登录用户的租户为边界。

## 后端设计

### 数据模型与迁移

- 在 `roles` 表和 `Role` 模型增加非空布尔字段 `is_builtin`，默认 `false`。
- 新增 Alembic 迁移：为已有角色添加字段，并将编码为 `SYSTEM_ADMIN`、`KNOWLEDGE_ADMIN`、`EMPLOYEE` 的初始化角色更新为内置角色。
- 种子数据创建上述角色时设置 `is_builtin=True`，以覆盖新建数据库和已初始化数据库两种场景。
- 继续使用现有 `permissions`、`role_permissions`、`user_roles` 表；不复制或重建既有 RBAC 关联。

### 领域分层

- `server/app/repositories/role_repo.py`
  - 按租户分页查询角色，同时返回用户数与权限数。
  - 查询指定租户内角色、批量校验权限 ID、读取并替换角色权限。
  - 统计角色关联用户数；删除角色时清理 `RolePermission` 并删除角色。
- `server/app/services/role_service.py`
  - 执行租户隔离、内置角色保护、编码唯一性、权限 ID 有效性、删除前用户关联校验和事务提交。
  - 将 ORM 记录转换为 API 所需的稳定响应结构。
- `server/app/schemas/role.py`
  - 定义角色列表、分页、详情、创建、更新、权限项以及统一错误所需的 schema。
- `server/app/api/v1/roles.py`
  - 独立注册角色 API，使用 `ROLE_READ` / `ROLE_WRITE` 控制读写权限。

### HTTP API

- `GET /api/v1/roles?keyword=&page=&pageSize=`：角色分页列表。
- `GET /api/v1/roles/{role_id}`：角色详情及已分配权限。
- `GET /api/v1/roles/available-permissions`：可分配权限，按模块和编码排序。
- `POST /api/v1/roles`：创建自定义角色。
- `PUT /api/v1/roles/{role_id}`：编辑自定义角色。
- `DELETE /api/v1/roles/{role_id}`：删除未关联用户的自定义角色。

路由注册顺序保证 `available-permissions` 在 `/{role_id}` 前匹配。读接口依赖 `ROLE_READ`，写接口依赖 `ROLE_WRITE`。

## 前端设计

### 页面与导航

- 新建 `features/role` feature，避免将角色 UI 混入 `features/org` 的用户页面。
- 侧边栏在“用户管理”之后增加“角色管理”条目，hash 路由为 `#roles`，使用 `ROLE_READ` 进行菜单和页面访问控制。
- `RolePage` 维持用户管理的页面结构：标题/说明、筛选栏、主列表面板、加载、空状态、错误提示、分页与移动端布局。

### 列表与交互

- 筛选栏提供关键字输入和“搜索”“重置”操作。
- 列表中的内置角色使用“内置”状态标签；自定义角色使用“自定义”标签。
- 有 `ROLE_WRITE` 的用户可看到“新增角色”按钮。
- 内置角色显示“查看”操作；自定义角色显示“编辑”“删除”。
- 删除需二次确认。若 API 返回关联用户限制，直接显示后端的明确错误消息。
- 每个行操作和表单均提供加载、禁用和失败提示，避免重复提交。

### 新增、编辑与查看

- 使用独立的 `RoleFormModal` 处理新增和编辑，使用只读模式显示内置角色详情。
- 字段为名称、编码、作用范围（只读 `TENANT`）和按模块分组的权限复选框。
- 编辑时加载详情并回显权限；内置角色进入只读模式，保存与删除入口不可用。
- 在窄屏下，表格隐藏表头并将角色属性堆叠到每行内容中，保持无水平溢出。

## 测试与验收

### 后端

- 覆盖角色列表的租户隔离、关键字过滤、分页、用户数和权限数。
- 覆盖创建、更新、重复编码和无效权限 ID 的错误处理。
- 覆盖内置角色禁止更新/删除，以及关联用户角色禁止删除。
- 覆盖删除自定义且未关联用户的角色会清理权限关联。
- 覆盖 API 的 `ROLE_READ` / `ROLE_WRITE` 权限边界。

### 前端

- 为角色 API 客户端、类型、页面和表单建立 TypeScript 静态检查。
- 在现有管理列表 Playwright 验收中加入角色页：菜单存在、列表数据渲染、桌面表头、移动端无水平溢出、内置角色只读、自定义角色操作可见。

### 完成标准

- 用户可从“角色管理”进入独立页面。
- 有读权限的用户能查看当前租户角色与权限信息；无读权限的用户看不到菜单且不能访问页面。
- 有写权限的用户能管理自定义角色及权限；内置角色不可修改或删除。
- 后端测试、前端类型检查、生产构建与角色页 Playwright 验收均成功。
